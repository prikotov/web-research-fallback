# Web Research Fallback

> Доступ к веб-источникам, к которым затруднен доступ. Для любого проекта и агента.

## Манифест

Политики и крупные корпорации ряда стран ограничивают доступ
к информации. Они хотят решать, что
человек должен знать, а что не должен. Однако право искать и получать информацию
закреплено международно и национально:

- **[Статья 19 Всеобщей декларации прав человека (1948)](https://www.un.org/ru/about-us/universal-declaration-of-human-rights)** — свобода искать,
  получать и распространять информацию и идеи любыми средствами и независимо
  от государственных границ. Декларация Генассамблеи ООН (резолюция 217 A (III)).
- **[Статья 19 Международного пакта о гражданских и политических правах (1966)](https://undocs.org/ru/A/RES/2200A(XXI))** —
  то же право в договорной форме. СССР подписал в 1968, ратифицировал 16.10.1973;
  Россия участвует (175 государств-участников).
- **[Статья 29 Конституции РФ, часть 4](http://www.kremlin.ru/acts/constitution)** — каждый имеет право свободно искать,
  получать, передавать, производить и распространять информацию любым
  законным способом.

Этот скилл помогает пользоваться этим правом: перебирает способы доступа
к открытым источникам — публичные архивы, зеркала — и фиксирует,
откуда и каким путём получена информация. Платные подписки и авторизацию
он не обходит: свобода информации не отменяет чужих прав.

## Зачем это нужно

Миссия — сделать информацию доступной, свободной от ограничений: сегментация
интернета, блокировки и фильтры не должны лишать агента и человека проверяемых
фактов.

Этот skill проверяет источники, которые не открываются с первой попытки,
и ищет материалы, когда адрес неизвестен.

- **Открывает то, что не открывается** — таймауты, 403/429, JS-challenge, гео-блоки: перебор способов доступа, включая прокси и архив Wayback
- **Работает из России** — исходящие блокировки, фильтры по IP и UA, сертификаты НУЦ Минцифры учтены в переборе способов
- **Подтверждает факты первоисточником** — тело страницы плюс способ и дата проверки; сниппеты поисковика — только для выбора URL
- **Ищет источники по теме** — когда адрес неизвестен: Tavily/Brave/Jina (API-ключи), Bing (ru-RU) и lite.duckduckgo выдают кандидатов (URL и сниппет), тело страницы берёт `fetch.php`

## Что вы получите

| Скрипт | Что делает |
|------|------------|
| `scripts/fetch.php` | Загружает содержимое адреса, перебирая способы доступа; тело сохраняет в файл, в stdout — JSON-отчёт о способе и попытках |
| `scripts/search.php` | Ищет источники по теме; в stdout — JSON со списком кандидатов (title, url, snippet) и сработавшим движком |

## Зависимости

PHP 8.4+ с расширением `curl` (`php -m | grep curl`). Без composer-зависимостей
и без внешних skills: общий клиент `WrfClient.php` лежит внутри репо.
Опционально: google-chrome/chromium для способа chrome (JS-challenge сайты).

## Использование

### fetch.php — загрузка содержимого

```bash
# Проверить закрытую статью: скрипт сам переберёт способы, тело — в /tmp
php scripts/fetch.php https://www.finam.ru/publications/item/dolya-fizlits-v-birzhevykh-torgakh-aktsiyami-v-oktyabre-sostavila-69-20251110-2119/

# Сохранить тело для разбора в конкретный файл
php scripts/fetch.php https://example.com/article --out /tmp/article.html

# Медленный сайт: больше времени на попытку
php scripts/fetch.php https://example.com/ --timeout 40

# Только direct+прокси, без архива
php scripts/fetch.php https://example.com/ --no-wayback

# Сайт вне карты FEEDS: явная лента для шага feed
php scripts/fetch.php https://example.com/article --feed https://example.com/rss.xml
```

#### Параметры fetch.php

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `URL` | Позиционный, обязательный: что проверяем | — |
| `--out` | Куда сохранить тело | `/tmp/wrf_<hash>.html` |
| `--timeout` | Секунд на попытку | 20 (вариации URL — 12) |
| `--no-wayback` | Не ходить в Wayback | выключено |
| `--feed` | Явная RSS/Atom-лента для шага feed | из карты FEEDS по хосту |
| `--no-chrome` | Не ходить в headless Chrome | выключено |
| `--proxy` | Прокси явно, поверх env и конфига | из env/конфига |

### search.php — поиск источников

```bash
# Найти источники по теме
php scripts/search.php "moex retail investors share 2021"

# Больше кандидатов для каталогизации
php scripts/search.php "объем торгов акциями вторичный рынок" --limit 20

# Только ddg
php scripts/search.php "обзор рисков финансовых рынков" --engine ddg
```

Движки без ключей в конфиге пропускаются; jina без прокси тоже (451 из РФ).
google/yandex/mail.ru не используем: enablejs, captcha и оболочка авторизации;
эмуляция Chrome не помогает — google прячет URL в /goto-токены
(проверено 2026-11-25, таблицы — `references/methods.md`).

#### Параметры search.php

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `"запрос"` | Позиционный, обязательный: формулировка как для поисковика | — |
| `--limit` | Сколько результатов вернуть | 10 |
| `--engine` | Движок: auto (tavily → brave → jina → bing → ddg), tavily, brave, jina, bing, ddg | auto |
| `--proxy` | Прокси явно, поверх env и конфига | из env/конфига |

### Через агента

После установки skill агент автоматически узнаёт о нём. Примеры запросов:

```
Страница не открывается — проверь источник и скажи, каким способом взял тело
```

```
Найди источники про долю физлиц в объёме торгов Мосбиржи
```

```
Я хочу понять по объемам кто торгует на московской бирже - основные торги
к которым у меня есть доступ, где у меня лежат акции, облигации.
Можешь найти информацию?
```

При выполнении этого запроса статья Reuters о нерезидентах на Мосбирже
(29.07.2021) была взята через Wayback+прокси: оригинал недоступен,
перепечатка Finam отдавала 403. Так скилл и работал в бою.

## Результаты

Тело страницы сохраняется в файл, отчёт печатается в stdout:

```
/tmp/wrf_3f2a9c01b7.html          # тело страницы (--out или дефолтный /tmp-файл)
stdout: {"ok": true, "method": "proxy", "status": 200, "bytes": 973149,
         "out": "/tmp/wrf_3f2a9c01b7.html", "attempts": […]}
```

Код выхода: 0 — тело получено, 1 — все способы мимо. Предупреждения
(например, пополнение .gitignore) идут в stderr, не в отчёт. Секретов
в отчётах нет: только имена способов и `proxy_available`.

## Конфиг и секреты

```bash
cp .wrf_config.example.json .wrf_config.json   # в корне репо
chmod 600 .wrf_config.json                    # затем заполнить "proxy" и ключи поисковых API
```

`.wrf_config.json` — в `.gitignore` этого репо. Поля: `proxy`,
`brave_api_key`, `tavily_api_key`, `jina_api_key` (ключи опциональны:
без них соответствующие движки пропускаются; jina-reader работает без ключа).
Порядок разрешения прокси:
`--proxy` → env `WEB_RESEARCH_PROXY` → `.wrf_config.json` (или путь из `WRF_CONFIG`).
Env-файлы проектов (`.env.dev.local`, `.env`…) скилл не читает.
В коммитах секретов нет и быть не должно.

При каждом запуске `fetch.php`/`search.php` проверяют, что конфиг закрыт
`.gitignore` того репо/каталога, где он лежит (включая случай, когда скилл
скопирован внутрь чужого репо): не закрыт — запись добавляется автоматически,
в stderr — предупреждение. Приём из `Ga4Client.php` (google-analytics-core).

## Как устроен перебор способов доступа

Порядок способов `fetch.php` (раздел для понимания и отладки):

1. **direct.** Сетевая ошибка (DNS/connect/timeout — типично для исходящих
   блокировок из РФ) → вариации пропускаем, сразу прокси: тот же способ и IP,
   вариации UA/схемы там бессмысленны и только жгут время.
2. **HTTP-отказ (403/429/5xx/JS-challenge)** → direct с браузерным UA
   (WAF фильтрует по UA), затем смена схемы http↔https (legacy-сайты без TLS).
   www-вариант не нужен: редиректы www скрипт следует сам.
3. **TLS-отказ (errno 60/35/77…)** — российские сайты на сертификатах НУЦ
   Минцифры, которых нет в дефолтном trust store. Прокси не лечит: доверие
   локальное. Бандл в репо не вендорим (у сертификатов есть срок жизни);
   отчёт возвращает `hint` с причиной и официальной ссылкой установки:
   https://www.gosuslugi.ru/crt. Сертификат, установленный в систему, лечит direct.
4. **proxy** (браузерный UA + полный набор браузерных заголовков) — меняет exit IP:
   гео-блоки и 429 по IP. HTTP-отказ через прокси → смена схемы через прокси.
5. **chrome** (приём из skills/news-web t-invest-agent): JS-challenge или
   JS-оболочка или пустое тело при 200 → headless Chrome `--dump-dom`.
   UA chrome обязан совпадать с платформой/версией реального браузера
   (Win/126 против Linux/146 — challenge фингерпринтит несоответствие).
   Авторизованный прокси chrome не умеет — chrome-proxy не пробуем.
6. **jina reader** (r.jina.ai через прокси): рендерит JS и отдаёт markdown;
   включается при challenge/js-shell/empty body, если chrome не помог или отключён.
   Работает без ключа; из РФ direct = 451, только прокси.
7. **feed** (опыт news-core): сайт закрыл HTML, но отдаёт RSS/Atom для
   агрегаторов. Карта известных лент — `WrfClient::FEEDS` (RBC full.rss с полными
   текстами, Interfax, TASS, RIA, 1prime, Kommersant); ищется item со ссылкой на
   целевой URL, тело = XML item. Явная лента — `--feed`. Лента ходит с системным
   trust, затем через прокси.
8. **Wayback**, если мёртв на всех способах: `archive.org/wayback/available`
   (обычно direct) → снапшот direct → при 429 снапшот через прокси.
   Пагинация и `?singlepage=1` — внутри снапшота.
9. **archive.today в переборе нет**: из РФ недоступен и direct, и через прокси
   (проверено 2026-11-25, оба 000).

## Российские CA (сертификаты НУЦ Минцифры)

Российские сайты (sberbank.ru, gosuslugi.ru, …) перешли на сертификаты
российского УЦ; дефолтный trust store их не знает → curl errno 60.
Бандл сертификатов в репо **не вендорим**: у них есть срок жизни
(корневой до 2032-02-27, промежуточный до 2027-03-06), а доверие должно быть
системным. При TLS-отказе отчёт возвращает `hint` с причиной и официальной
страницей установки: **https://www.gosuslugi.ru/crt** (Госуслуги — портал
Минцифры; банковские страницы вроде sberbank.ru/ru/certificates — зеркала).
Установленный в систему корневой сертификат лечит direct без всяких опций.

## Правила

- Не выводить прокси/токены в stdout, логи, файлы, отчёты; никаких `curl -v` с прокси.
- Не отключать проверку сертификатов (`-k`): при TLS-отказе — `hint` с официальной ссылкой установки.
- Не обходить подписки/авторизацию; Wayback — публичный архив.
- Rate limit уважать; временные файлы — в `/tmp`.
- «Не проверено» фиксировать явно; из сниппетов поисковика информацию не брать —
  они только для выбора URL, факт из тела страницы.
