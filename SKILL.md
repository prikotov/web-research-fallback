# Web Research Fallback

Навык: проверить недоступный источник, а не сдаться после первой ошибки.
Скрипты сами проходят цепочку маршрутов и возвращают JSON-отчёт; агент читает
отчёт, фиксирует маршрут и дату в карточке источника и решает, что делать
дальше. Установка, требования и устройство клиента — в README.md.

## Скрипты

### fetch.php — `scripts/fetch.php`

Достаёт тело недоступного URL, сам проходя цепочку маршрутов
(direct → вариации UA/схемы/www → прокси → Wayback). Тело сохраняет в файл,
в stdout печатает JSON-отчёт о том, каким маршрутом и с какими попытками
удалось (или не удалось) получить содержимое.

Что получаешь в отчёте:
- `ok`, `route`, `status`, `bytes` — итог: каким маршрутом взято тело;
- `out` — путь к сохранённому телу (читать дальше его, а не stdout);
- `attempts[]` — каждый маршрут со статусом и пометкой (`challenge`,
  `curl errno N`, `no snapshot`): где именно цепочка сломалась;
- `proxy_available` — был ли прокси в рантайме (если нет — цепочка короче).

```bash
php scripts/fetch.php https://example.com/article --out /tmp/article.html
php scripts/fetch.php https://example.com/ --timeout 40 --no-wayback
```

Параметры:
- `URL` — позиционный, обязательный: что проверяем.
- `--out FILE` — куда сохранить тело; без него — `/tmp/wrf_<hash>.html`.
- `--proxy URL` — прокси явно, поверх env и конфига.
- `--timeout N` — секунд на попытку (по умолчанию 20; вариации URL — 12).
- `--no-wayback` — не ходить в Wayback (когда архив заведомо не нужен).

Код выхода: 0 — тело получено (200 без JS-challenge), 1 — все маршруты мимо.
`ok=false` не значит «источника нет»: смотри `attempts` и раздел «Цепочка».

### search.php — `scripts/search.php`

Ищет URL источников по теме, когда адрес неизвестен или нужно набрать
материалов. Поиск через lite.duckduckgo.com (POST `q=`), при неудаче direct —
через прокси. В stdout — JSON со списком найденного.

Что получаешь:
- `results[]` — `{title, url, snippet}`: заголовок, адрес, сниппет выдачи;
- `route`, `status` — каким маршрутом искал.

```bash
php scripts/search.php "moex retail investors share 2021" --limit 8
```

Параметры:
- `"запрос"` — позиционный, обязательный; формулировка как для поисковика.
- `--limit N` — сколько результатов вернуть (по умолчанию 10).
- `--proxy URL` — прокси явно, поверх env и конфига.

Сниппет — не проверенный факт: каждый перспективный URL открывай через
`fetch.php` и фиксируй маршрут в карточке источника.

### Прокси (общий для обоих скриптов)

Порядок разрешения: `--proxy` → env `WEB_RESEARCH_PROXY` → собственный конфиг
скилла `.wrf_config.json` (путь можно задать через `WRF_CONFIG`); настройка —
в README. Значение прокси не выводится ни в stdout, ни в отчёты, ни в файлы;
в отчётах только имена маршрутов и `proxy_available`.

## Когда использовать

Сайт не отвечает при исследовании: connect/read timeout, HTTP 000/403/502/429,
JS-challenge («Just a moment», «Client Challenge»). Не делай вывод «источник
недоступен» после первой попытки — пройди цепочку (скрипт делает её сам).

## Цепочка доступа (порядок)

1. **Диагностируй ошибку.** Различай connect timeout (сеть/блокировка), read
   timeout (сервер молчит), 403 (блок/гео), 429 (rate limit), 502 (прокси не
   достучался до origin). 🔴 Никогда `curl -v` с прокси: debug печатает URL
   прокси с учётными данными.
2. **Повтори напрямую с вариациями:** браузерный UA, http/https, www/без www,
   timeout до 45–60 с.
3. **Повтори через прокси** (меняет exit IP: гео-блоки и 429 по IP). Пробуй
   https и http через прокси.
4. **Сайт мёртв на обоих маршрутах → Wayback:** `archive.org/wayback/available`
   (обычно direct), CDX `web.archive.org/cdx/search/cdx?url=…&filter=statuscode:200`,
   снапшот `web.archive.org/web/<ts>/<URL>`; при 429 — через прокси. Пагинацию
   и `?singlepage=1` проверяй внутри снапшота.
5. **JS-challenge (Scribd и т.п.):** Wayback; не вышло — статус «не проверено»,
   содержимое не додумывать.
6. **Зафиксируй маршрут и дату** в карточке источника/отчёте проекта: что
   пробовал, итог «проверено (маршрут, снапшот)» или «не проверено». Отсутствие
   доступа ≠ отсутствие содержимого; сниппет поисковика ≠ проверенный факт.

## Безопасность

- Секреты — только собственный конфиг скилла (в `.gitignore`) или рантайм-env;
  не в код, коммиты, логи, отчёты, заметки. Env-файлы проектов (.env…) не читаем.
- **Защита от коммита секрета:** при каждом запуске скрипт проверяет, что конфиг
  закрыт `.gitignore` того репо/каталога, где он лежит; не закрыт — сам пополняет
  .gitignore именем файла и предупреждает в stderr; значение секрета не выводится.
- Временные файлы — в `/tmp` (fetch.php по умолчанию), не мусорить в проекте.
- Не обходить платные подписки и авторизацию; Wayback — публичный архив.
- Уважать rate limit: паузы, не долбить 429.
